# PROHOR PWA policy (Day 1)

One responsive Next.js web app; installed PWA is the same application. There is no React Native/native code in this starter.

## What is implemented

- App Router manifest at `/manifest.webmanifest` (generated by Next), 192/512 icons and maskable icon.
- Browser service worker registration plus optional install control where `beforeinstallprompt` exists.
- Offline informational fallback page, minimal public asset caching and eligible public Shonket safety pages after a successful online visit.
- `display: standalone`, responsive viewport, touch targets and phone bottom navigation.
- Theme is selected independently of accessibility preferences; original token CSS imported unchanged.

## Sensitive caching policy

**Do not cache:** `/app`, `/api`, `/auth`, `/sign-in`, `/ask`, `/find-care`, patient/provider JSON, medical documents, chat, private notes, AI responses, location-specific care metadata. The service worker may cache only successful, anonymous HTML navigations for the public `/safety` index and its four warning-topic pages, when the server response is explicitly cacheable, has no `Set-Cookie`, and does not vary by cookies. Pages with query strings and all failed/private/no-store responses are excluded. These pages contain only public preview content; no medical records or submitted concern data are stored.

Do not store PHI in localStorage, service worker caches, telemetry or generic IndexedDB. The included preference utility stores _presentation choices only_ in localStorage.

Never queue a human-support request offline and then claim it was sent. A future encrypted offline draft system requires separate threat modeling, user consent, device-sharing assumptions and tested synchronization.

## Test on installed Android (Chrome)

1. Deploy on HTTPS, load site, inspect manifest/icons and install option.
2. Open standalone app: keyboard and focus must remain usable.
3. Enable airplane mode: offline fallback must be truthful; no stale safety/clinic data claims.
4. Verify DevTools Application → Cache Storage contains no user-specific data or private routes.
5. Restore network and validate preferences persist without losing user draft state.
6. iOS Safari installation differs and does not guarantee the `beforeinstallprompt` event; use browser's Add to Home Screen workflow.
7. Re-test when service worker caching policy changes; bump CACHE version.

**Not shipped in starter**: offline clinical records, push notifications, background sync, SMS, authenticated provider messaging, reliable AI, real report extraction.
