## Scope of THIS package

The scripts build a nationwide **candidate research queue** from an exported government HRIS organization list, then safely import only **manually verified individual facility rows**. It does not fabricate records or automatically treat 39k organization entries as 39k healthcare facilities. The public DGHS/HRIS registry covers many kinds of organizations; its documented bulk API requires authentication.

## Workflow — Windows PowerShell 5.1

1. Use `E:\PROJECTS\Hackethon\Main Task\prohor-ifteelasminute` on `iftee-lastminute`.
2. Install the new scripts in `scripts/` without overwriting existing files; `next-env.d.ts` is generated by Next dev and should not be staged.
3. From [DGHS/HRIS Facility Registry](https://hrm.dghs.gov.bd/public/facility-registry/reports/organization-list), export the **organization list** as CSV with name, type, district, code, area. Do not share credentials or private data.
4. Generate an unreviewed clinical review queue:

   `node scripts/poth-registry-to-review-queue.mjs "F:\DOWNLOADS\hris-export.csv" "F:\DOWNLOADS\poth-nationwide-review.csv"`

5. Inspect each candidate's **individual registry profile**, confirm facility identity and physical location, copy the *facility-specific* URL. Mark reviewed YES ONLY after checking the source. If a specific profile link does not exist, leave NO; leave phone/services blank without specific evidence. A facility's presence does not establish current clinical capabilities.
6. First DRY RUN the import:

   `node scripts/poth-facilities-from-csv.mjs "F:\DOWNLOADS\poth-nationwide-review.csv"`

7. After spot-check and peer review, apply:

   `node scripts/poth-facilities-from-csv.mjs "F:\DOWNLOADS\poth-nationwide-review.csv" --write`

8. Run `npm.cmd run typecheck`, `npm.cmd run lint`, `node scripts/PROHOR-Poth-FinalCheck-20261118.mjs`, `npm.cmd run build`.
9. Launch app and test `/poth`, `/find-care`, `/api/poth/facilities`, query filtering, and one real source URL per selected district.
10. Git stage *only* the verified `facilities.json` and approved scripts/docs, after reviewing `git diff --cached`. Fetch and confirm remote HEAD; push **only** `iftee-lastminute` after all checks pass and Samin/Omor review. Never force push.

## What can be publicly claimed?

- "Nationwide district filter" describes UI reach, not healthcare provider coverage.
- "Government-registry-sourced facility identities" applies to entries individually checked against government profiles. It does not mean independently verified services.
- Every accessibility feature remains **unknown/not verified**; booking remains **not integrated**.
- `999` merely launches the dialer; it does not dispatch an ambulance or transmit location.

## Important limitations

- Not a complete nationwide directory yet. Actual number of published facilities depends on source review.
- Registry export formats vary; queue generator supports common English column headers and filters *likely* patient-facing organization types, with false positives/omissions possible. Its output must be reviewed.
- The importer requires a facility-specific DGHS/HRIS HTTPS URL, and rejects repeated source URLs, malformed locations, malformed phones, duplicate facilities, and imports that would shrink a previously populated directory.
- Data import makes a local backup `facilities.json.pre-national-import.bak` (do not stage this file) and writes atomically.
