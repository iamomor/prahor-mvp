## User job, paths and risk

The mother chooses a named simulated provider, purpose, exact fields, reply permission and expiry; reviews the complete decision; explicitly approves it; then follows the saved request or withdraws future access. This handles private synthetic records and consent. It provides no emergency monitoring or real clinical service.

The public entry is `/bondhon`; the private mother and provider entries are `/app/bondhon` and `/provider/bondhon`. Shonket preparation → `/app/care/review` → saved status remains available. Both creation entries now use the same labelled form, focused review, unchecked approval and atomic write. Poth emergency information remains independently reachable. Network uncertainty freezes the reviewed submission and preserves its retry key rather than claiming delivery.

## Changes and compatibility review

- Required `coordination` for every new HTTP care request. Missing approval, expiry or explicit reply choice is rejected before a domain write.
- Added forward migration `20261119060000_require_request_permission.sql`. It removes direct application execution of the legacy creation RPC. The security-definer coordinator can still call that building block internally. Existing historical request reads/actions are preserved; no tables or medical records are dropped or rewritten.
- Replaced Shonket's separate multi-write submit logic with the existing Bondhon form. Retained its step heading, prepared message, communication method, status route and request-history registration. Edits carry back to preparation, including temporarily clearing the message without unmounting the editor. Nothing is preselected for sharing. New request consent and grants are one transaction.
- Corrected the Shonket status page to show the recorded expiry instead of always promising seven days.
- Extended Bondhon button wrapping to its read-aloud control and allowed the shared mother header to wrap at 200% text. Semantic tokens and existing components remain in use.
- Expanded the read-only SQL inspector with forced RLS, table privileges, public RPC privileges and internal helper execution checks.

The historical care database suite intentionally exercises the migration chain before the new hardening migration. The Bondhon suite exercises the full forward chain and proves that legacy creation is denied while pre-existing requests still work. The SQL-backed HTTP suite now creates requests through the coordinated path.
